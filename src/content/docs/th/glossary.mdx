ศัพท์ของ Svelte 5 เน้นที่ rune เป็นหลัก — `$state`, `$derived` และ `$effect` เข้ามาแทนที่ `export let`, `$:` และ `<slot>` — บวกกับ async Svelte (`await` ใส่ตรง ๆ ใน `$derived` และใน template ได้ ต้องเปิดผ่าน `experimental.async`) และฝั่ง SvelteKit ก็มีทั้ง routing, hooks และ remote functions ต่อยอดเข้ามาอีกชั้น เวลาอ่านบทเรียนแล้วเจอคำที่ไม่คุ้น หรือไม่แน่ใจว่ายังใช้ได้อยู่กับ Svelte 5.57 / SvelteKit 2.70 ไหม ให้กลับมาดูที่นี่

## A

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| action / `use:` | directive แบบเก่า: function ที่รับ DOM node ของ element (พร้อม param ทางเลือก) ตอน mount แล้วอาจคืน `{ update?, destroy? }` เอกสารของ Svelte เองตอนนี้แนะนำให้ใช้ attachment กับโค้ดใหม่แล้ว แต่ `use:` ก็ยังใช้ได้อยู่ และยังเป็นสิ่งที่ library แบบ pre-attachment หลายตัวส่งมาให้เราตรง ๆ | [Actions](/svelte/th/bindings-actions-transitions/actions/) |
| adapter | plugin (`@sveltejs/adapter-node`, `-static`, `-cloudflare`, `-auto`, …) ที่บอก `vite build` ว่าจะแพ็ก SvelteKit app ให้เข้ากับ target ที่จะ deploy ยังไง — Node server แบบ standalone, static site ที่ prerender ล้วน หรือ format แบบ edge/worker เฉพาะ platform | [Server & API](/svelte/th/sveltekit/server-and-api/) |
| `animate:flip` | directive จาก `svelte/animate` ที่เลื่อน item ของ `{#each}` แบบ **keyed** ไปตำแหน่งใหม่อย่างนุ่มนวลเมื่อ list เรียงลำดับใหม่ — transition อย่างเดียวครอบคลุมแค่ add/remove เพราะ keyed reorder ใช้ DOM node เดิมซ้ำ ไม่มี intro/outro เกิดขึ้นเลย | [Transitions & Animations](/svelte/th/bindings-actions-transitions/transitions-and-animations/) |
| `$app/navigation` | module ที่ใช้ได้เฉพาะฝั่ง client export `goto()` สำหรับ navigate แบบสั่งเอง, `invalidate()`/`invalidateAll()` เพื่อบังคับให้ `load` รันใหม่ และ lifecycle hook `beforeNavigate`/`afterNavigate` รอบ ๆ การเปลี่ยน route | [Server & API](/svelte/th/sveltekit/server-and-api/) |
| `$app/state` vs `$app/stores` | `$app/state` เปิด `page`, `navigating` และ `updated` เป็น runed object ธรรมดาให้อ่านตรง ๆ (`page.data`); `$app/stores` เปิดข้อมูลชุดเดียวกันเป็น Svelte store ที่ต้องมี `$` นำหน้า ตอนนี้ deprecate แล้วเพื่อให้ใช้แบบแรกแทน | [Loading Data](/svelte/th/sveltekit/loading-data/) |
| async Svelte / `experimental.async` | ชุดฟีเจอร์ที่ให้ใส่ `await` ตรง ๆ ใน `$derived` และใน template ของ component ได้เลย ไม่ใช่แค่ใน `<script>` ระดับบนสุด ต้องเปิดผ่าน compiler option `experimental.async: true` ไม่งั้น Svelte จะขึ้น error จริง ๆ ทันทีที่เจอ `await` ในตำแหน่งเหล่านั้น | [Async Svelte](/svelte/th/reactivity/async-svelte/) |
| attachment / `{@attach}` | function ที่ใส่ผ่าน `{@attach fn}` รันตอน element ของมัน mount และคืน cleanup function ที่รันตอน unmount ได้ เปิดตัวใน Svelte 5.29 เป็นตัวสืบทอดที่ยืดหยุ่นกว่าของ `use:` action — ใช้กับ component ได้ด้วย ซึ่ง `use:` ทำไม่ได้ | [Actions](/svelte/th/bindings-actions-transitions/actions/) |

## B–C

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| batching / microtask | Svelte รวม DOM update เป็น batch: effect (รวมถึงตัวที่อยู่เบื้องหลัง `onMount`) รันบน microtask หลังจาก `mount()`/`hydrate()` คืนค่ากลับมาแล้ว ไม่ใช่แบบ synchronous — นี่แหละคือเหตุผลที่อ่านค่าที่เพิ่งเปลี่ยนทันทีหลังจากนั้นอาจยังเห็นค่าเก่าอยู่ จนกว่า `flushSync()` หรือ microtask ถัดไปจะตามให้ทัน | [Lifecycle](/svelte/th/components/lifecycle/) |
| `$bindable` | rune ที่ component ต้องใส่ให้ prop ที่ destructure ออกมา (`let { value = $bindable() } = $props()`) ก่อนที่ parent จะ `bind:` เข้ามาได้ ถ้าไม่ใส่ การ `bind:` เข้า prop นั้นจะเป็น compile error จริง ๆ ที่ถูกจับได้ ไม่ใช่แค่เงียบ ๆ ไม่ทำอะไร | [Props & $bindable](/svelte/th/reactivity/props-and-bindable/) |
| `bind:` / function bindings / `bind:this` / `bind:group` | `bind:` คือ syntax sugar ของค่า + event ที่เปลี่ยนมัน (`bind:value`, `bind:checked`, `bind:files`); `bind:group` ผูก radio/checkbox ทั้งกลุ่มเข้ากับตัวแปรเดียว; `bind:this` เก็บ DOM node หรือ instance ของ component หลังจาก mount แล้ว; และตั้งแต่ Svelte 5.9 binding ก็รับคู่ function `{get, set}` แทน identifier ธรรมดาได้ เพื่อ validate หรือแปลงค่าตอนที่มันไหลเข้ามา | [Bindings](/svelte/th/bindings-actions-transitions/bindings/) |
| children | snippet prop เริ่มต้น: markup อะไรก็ตามที่ parent วางซ้อนไว้ข้างในแท็กของ component จะมาถึงในรูป prop `children` render ด้วย `{@render children?.()}` — ตัวแทนแบบมี type และรับ parameter ได้ของ Svelte 5 สำหรับ `<slot>` แบบไม่ตั้งชื่อรุ่นเก่า | [Passing UI & Children](/svelte/th/components/passing-ui-and-children/) |
| `class={{...}}` / `style:` | ตั้งแต่ Svelte 5.16 attribute `class` ธรรมดารับ object หรือ array ได้เลย (`class={{ active: isActive }}`, `class={[a, b && 'c']}`) ประมวลผลด้วย algorithm เดียวกับ helper ยอดนิยม `clsx` ที่ built-in อยู่ในตัว compiler ไม่ต้องลง dependency เพิ่ม; `style:prop={value}` ตั้งค่า CSS property เดียวแบบ reactive โดยไม่แตะส่วนอื่นของ `style` | [Events & Attributes](/svelte/th/foundations/events-and-attributes/) |
| compiler / runes mode / legacy mode | compiler ของ Svelte เป็น static analyzer ที่ตัดสินทีละไฟล์ว่าไฟล์นั้นอยู่ใน **runes mode** (มี rune ตัวใดก็ได้ หรือ `runes: true`) หรือ **legacy mode** — ทั้งสองเป็นเส้นทางโค้ดคนละสาย ดังนั้นการผสม reactivity primitive ข้ามสองโหมด (`export let` กับ `$state`, `$:` กับ `$derived`) จึงเป็น compile error จริง ๆ ไม่ใช่แค่ warning | [Why Svelte, the Compiler](/svelte/th/foundations/why-svelte-the-compiler/) |
| context (`setContext`/`getContext`) | `setContext(key, value)` ให้ ancestor ส่งค่าไปถึง descendant ทุกตัวได้โดยไม่ต้องส่งผ่าน prop ทีละชั้น (หลีกเลี่ยง prop drilling); `getContext(key)` อ่านค่าจาก ancestor ที่ใกล้ที่สุด `setContext` รันแค่ครั้งเดียวตอน init ดังนั้นค่าที่ส่งเข้าไปต้องเป็น runed object (อย่าง `$state`) อยู่แล้ว descendant ถึงจะเห็น update ทีหลังได้ | [The Context API](/svelte/th/components/context-api/) |
| `createAttachmentKey` | สร้าง symbol key ที่ไม่ซ้ำกัน จาก `svelte/attachments` ใช้ทำเครื่องหมายว่า property ของ object นี้เป็น attachment เมื่อ spread object นั้นลงบน element (`{...stuff}`) — เป็นทางเลือกแบบ programmatic แทนการเขียน `{@attach fn}` ตรง ๆ เหมาะกับตอนสร้าง attachment หลายตัวจาก loop หรือรวมจากหลายแหล่ง | [Actions](/svelte/th/bindings-actions-transitions/actions/) |
| `createEventDispatcher` (legacy) | วิธีของ Svelte 4 ในการยิง custom event (`dispatch('change', detail)`) ให้ parent ดักด้วย `on:change` มันยังคอมไพล์ผ่านโดยไม่มี warning เลยแม้อยู่ใน runes mode แต่ callback prop (`onchange?.(detail)`) คือตัวแทนที่ถูกต้องแบบ Svelte 5 | [Events & Attributes](/svelte/th/foundations/events-and-attributes/) |
| `createSubscriber` | primitive ระดับล่างจาก `svelte/reactivity` ที่ reactive wrapper แบบ built-in ทุกตัว (`MediaQuery`, ค่าจาก `svelte/reactivity/window`) ถูกสร้างขึ้นบนมัน: ส่ง callback ที่ subscribe แหล่งข้อมูลภายนอกแบบ push แล้วเรียก `update()` ให้มัน มันจะเชื่อม notification จากแหล่งนั้นเข้ากับ dependency tracking ของ Svelte เองผ่าน getter ธรรมดา | [Built-in Stores](/svelte/th/state-and-stores/built-in-stores/) |
| CSP (Content-Security-Policy) | config `kit.csp` ของ SvelteKit (ใช้แบบแบน ๆ ใน config ของ plugin `sveltekit()` สำหรับ Vite ก็ได้) สร้าง nonce header จริง ๆ ต่อ request ให้อัตโนมัติ ทำให้ inline script/style ที่ framework ต้องใช้ผ่าน Content-Security-Policy แบบเข้มงวดได้โดยไม่ต้องจัดการ nonce เอง | [Server & API](/svelte/th/sveltekit/server-and-api/) |
| custom element | Web Component แบบ native ที่ Svelte compile component ให้กลายเป็นได้ผ่าน `<svelte:options customElement="tag-name">` ผู้ใช้ใน framework *ไหนก็ได้* (หรือไม่ใช้ framework เลย) เรียกใช้มันเหมือน DOM element ทั่วไป และ `$host()` คือวิธีที่ component เข้าถึง element ที่ host ตัวมันจากข้างใน | [Advanced Runes](/svelte/th/reactivity/advanced-runes/) |

## D–E

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| deep reactivity / proxy | `$state` บน object หรือ array จะห่อค่านั้นด้วย Proxy ทำให้การเขียน property ธรรมดาและการ mutate array (`arr.push(x)`, `obj.prop = y`) ถูก track อัตโนมัติในทุกระดับความลึกของโครงสร้าง — ไม่ต้องมี "setter" แยกต่างหากเหมือน store ธรรมดา | [The $state Rune](/svelte/th/reactivity/state-rune/) |
| dependency tracking | compiler ตัดสินแบบ static ว่าการอ่านค่าไหนใน `$derived`/`$effect` นับเป็น dependency — การวิเคราะห์นี้ทำก่อนที่โค้ดของเราจะรันด้วยซ้ำ และเป็นสิ่งที่ทำให้ Svelte สร้าง update แบบละเอียด (fine-grained) แทนที่จะ re-render ทั้ง component | [Why Svelte, the Compiler](/svelte/th/foundations/why-svelte-the-compiler/) |
| `depends()` / `invalidate()` | `depends(key)` ข้างใน `load` function ลงทะเบียน dependency string แบบกำหนดเอง แล้วเรียก `invalidate(key)` (หรือ `invalidateAll()`) จากที่ไหนก็ได้ทีหลัง จะบังคับให้ทุก `load` ที่ประกาศ dependency นั้นรันใหม่ — วิธี trigger การ refetch เองนอกเหนือจากการรันใหม่อัตโนมัติตาม URL/param | [Loading Data](/svelte/th/sveltekit/loading-data/) |
| `$derived` | ประกาศค่าที่คำนวณจาก reactive state อื่น (`let double = $derived(count * 2)`) ต่างจาก `$effect` ตรงที่การคำนวณใหม่ของมันเป็นแบบ **push-pull** และ lazy — dependency เปลี่ยนแค่ทำเครื่องหมายว่ามัน dirty เท่านั้น ตัว function จะรันจริงตอนที่มีอะไรมาอ่านมันครั้งถัดไป ไม่ใช่ตามตารางของตัวเอง | [The $derived Rune](/svelte/th/reactivity/derived-rune/) |
| `$derived.by` | รูปแบบ function ของ `$derived` สำหรับการคำนวณที่ต้องมากกว่าหนึ่ง expression — loop, ตัวแปรชั่วคราว, การแตกเงื่อนไข `$derived(expr)` ก็แค่ตัวย่อของ `$derived.by(() => expr)` ที่มี dependency tracking และความ lazy เหมือนกันทุกประการ | [The $derived Rune](/svelte/th/reactivity/derived-rune/) |
| `$effect` | ลงทะเบียน side effect ที่รันหลัง DOM update เสร็จ รันใหม่ทุกครั้งที่ค่าที่มันอ่านตอนรันล่าสุดเปลี่ยนไป cleanup function ที่มันคืนกลับมาจะรันก่อนรันรอบถัดไปและตอน unmount ถ้าเป้าหมายจริง ๆ คือแค่คำนวณค่า ให้ใช้ `$derived` แทน | [The $effect Rune](/svelte/th/reactivity/effect-rune/) |
| `$effect.pending` | รายงานจำนวน async update ที่กำลังค้างอยู่ข้างใน `<svelte:boundary>` ที่ใกล้ที่สุด — โดยเฉพาะกรณีที่ snippet `pending` ของ boundary เองไม่ครอบคลุม: async update *รอบถัดไป* หลังจาก render รอบแรกของ boundary resolve ไปแล้ว | [Async Svelte](/svelte/th/reactivity/async-svelte/) |
| `$effect.pre` | คู่ของ `$effect` ที่รัน **ก่อน** DOM update แทนที่จะรันหลัง — สำหรับอ่าน layout (เช่น scroll position) ที่ update ที่กำลังจะเกิดขึ้นจะไปเปลี่ยนมัน มีกติกา dependency-tracking และ cleanup เหมือนกับ `$effect` ทุกอย่าง | [The $effect Rune](/svelte/th/reactivity/effect-rune/) |
| `$effect.root` | สร้าง effect scope ที่ **ไม่** ถูกเลิกให้อัตโนมัติโดย parent — มันคืน function `destroy` กลับมาให้เราต้องเรียกเอง เป็นทางออกสำหรับ effect ที่สร้างนอก lifecycle ปกติของ component (state library, test, โค้ดที่ integrate แบบ imperative) | [Advanced Runes](/svelte/th/reactivity/advanced-runes/) |
| `$effect.tracking` | คืน `true` เมื่อโค้ดที่กำลังรันอยู่ตอนนี้อยู่ใน tracking context — effect, derived หรือ template — และคืน `false` นอกจากนั้น มีประโยชน์เวลาสร้าง reactive abstraction เองที่ต้องรู้ว่าตอนนี้ถูกอ่านแบบ reactive อยู่หรือเปล่า | [Advanced Runes](/svelte/th/reactivity/advanced-runes/) |
| `$env/static` vs `$env/dynamic` | `$env/static/private|public` ฝัง environment variable เป็นค่า literal ตอน **build time**; `$env/dynamic/private|public` อ่านค่าแบบสด ๆ ตอน **runtime** แทน — ความต่างนี้สำคัญเพราะค่าแบบ static ที่ถูกอบเข้า image แล้วเปลี่ยนไม่ได้จนกว่าจะ build ใหม่ ในขณะที่ค่าแบบ dynamic เปลี่ยนได้ | [Server & API](/svelte/th/sveltekit/server-and-api/) |
| `+error.svelte` | หน้า error เฉพาะของแต่ละ folder render เมื่อ `load` (หรือ page/layout เอง) throw ใน subtree นั้น SvelteKit จะไล่ขึ้น**ไปข้างบน**ใน route tree จากจุดที่ error เกิด เพื่อหาไฟล์ที่ใกล้ที่สุด ถ้าไม่มี ancestor ไหนใกล้กว่า ก็จะตกไปถึง `+error.svelte` ที่ root | [Routing & Pages](/svelte/th/sveltekit/routing-and-pages/) |
| event delegation | Svelte ไม่ได้ผูก native listener ให้ทุก element ที่มี `onclick` — มันลงทะเบียน listener ตัวเดียวที่ root ของแอปแล้วส่งต่อไปยัง handler ที่ถูกต้องจากตรงนั้น เพื่อลด memory footprint ผลที่ตามมาคือ `addEventListener` ธรรมดาระหว่าง root กับ element ของเราที่เรียก `stopPropagation()` บน native event จะทำให้ handler ของ Svelte ไม่ทำงานเลยแบบเงียบ ๆ | [Events & Attributes](/svelte/th/foundations/events-and-attributes/) |
| `event.locals` | object ต่อ request ที่ hook อย่าง `handle` เติมค่าให้ (`event.locals.user = ...`) เพื่อให้ `load` function, action และ handler ใน `+server.js` ที่อยู่ถัดไปอ่านได้ การ type ให้มันต้องผ่าน interface `App.Locals` ใน `src/app.d.ts` ไม่งั้นทุกจุดที่อ่านจะเป็น `any` โดยปริยาย | [Server & API](/svelte/th/sveltekit/server-and-api/) |
| `export let` (legacy) | วิธีของ Svelte 4 ในการประกาศ prop เมื่อ component ใช้ rune ตัวใดก็ตาม `export let` จะกลายเป็น compile error จริง ๆ แทนที่จะเป็น warning เพราะการ rewrite reactivity ของ runes mode ไม่เหลือความหมายให้มันแล้ว — `let { x } = $props()` คือตัวแทนของ Svelte 5 | [Events & Attributes](/svelte/th/foundations/events-and-attributes/) |

## F–H

| SSR | server-side rendering: SvelteKit render HTML ของ route บน server เป็นค่า default ก่อนที่ client จะ hydrate — โหมดนี้เองที่ทำให้ module-scope `$state` singleton อันตราย (แชร์กันข้ามทุก request ที่เกิดพร้อมกันบน process นั้น) ถ้าไม่สร้าง state ใหม่ต่อ request ผ่าน context แทน | [SvelteKit: Full-Stack Svelte](/svelte/th/sveltekit/) |
| `$state` | ประกาศค่า reactive (`let count = $state(0)`) บน object หรือ array มันห่อค่าด้วย Proxy เพื่อให้เกิด deep reactivity ดังนั้นการเขียน property ธรรมดาและการ mutate array จะถูก track ไม่ใช่แค่การ assign ค่าทั้งก้อนใหม่เท่านั้น | [The $state Rune](/svelte/th/reactivity/state-rune/) |
| `$state.raw` | ทำให้ค่าหลุดออกจาก Proxy ที่ `$state` ปกติจะห่อให้กับ object/array — มีแค่การ reassign ตัวแปรทั้งก้อนเท่านั้นที่นับเป็นการเขียน การ mutate เนื้อหาข้างในเปลี่ยนข้อมูลจริงแต่ไม่แจ้งใครเลย แลก deep reactivity กับประสิทธิภาพที่ได้จากการข้าม proxy instrumentation | [The $state Rune](/svelte/th/reactivity/state-rune/) |
| `$state.snapshot` | เอาสำเนาแบบธรรมดาที่ไม่ผ่าน proxy ของค่า `$state` ออกมา — ไว้ส่งให้ API (`api.save(...)`) หรือโค้ดใด ๆ ที่ไม่คาดหวัง (หรือจะทำงานผิดพลาดกับ) Proxy โดยไม่กระทบ reactive state ต้นฉบับ | [The $state Rune](/svelte/th/reactivity/state-rune/) |
| `$store` auto-subscription | การใส่ `$` นำหน้า store ข้างในไฟล์ `.svelte`/`.svelte.js` เป็น syntax sugar ของ compiler ที่ subscribe ให้แทนเรา อ่านค่าปัจจุบัน re-render ตอนเปลี่ยน และ unsubscribe อัตโนมัติตอน destroy — แต่ใช้ได้แค่ที่ **top level** ของ component เท่านั้น ไม่ใช่ข้างในฟังก์ชันหรือ block ที่ซ้อนอยู่ เพราะ compiler วาง subscription แบบ static ตรงนั้นไม่ได้ | [The Store Contract](/svelte/th/state-and-stores/the-store-contract/) |
| store contract | นิยามทั้งหมดของ Svelte store: object ใดก็ตามที่มี method `subscribe(fn)` ที่เรียก `fn` ทันทีด้วยค่าปัจจุบัน แล้วเรียกอีกทุกครั้งที่เปลี่ยน คืน function สำหรับ unsubscribe กลับมา — แค่นี้ก็พอแล้ว นี่คือเหตุผลที่ RxJS observable หรือ object ของ library อื่น ๆ ก็เป็น store ได้เหมือนกัน | [The Store Contract](/svelte/th/state-and-stores/the-store-contract/) |
| streaming (un-awaited promise) | การคืน promise จาก `load` โดย**ไม่** await มัน ทำให้ SvelteKit ส่งส่วนที่เหลือของหน้าออกไปทันที แล้วค่อย stream ค่านั้นเข้ามาทีหลังตอนมัน resolve อ่านได้ฝั่ง client ด้วย `{#await}` — ตรงข้ามกับการ await มันตรง ๆ ใน `load` ซึ่งจะทำให้ response แรกต้องรอจนกว่ามันจะเสร็จ | [Loading Data](/svelte/th/sveltekit/loading-data/) |
| `<svelte:boundary>` | กัก error ของ render หรือ effect ที่ throw ที่ไหนก็ตามใน subtree ของมันไว้ แทนที่จะปล่อยให้มัน unmount component tree ทั้งก้อนรอบข้าง มันยังโชว์ snippet `pending` ระหว่างที่ `await` ที่อยู่ตรง ๆ ใน template ของมันเอง resolve ครั้งแรก — ทั้ง async และ error handling อยู่บน element เดียวกัน | [Lifecycle](/svelte/th/components/lifecycle/) |
| `svelte-check` | type-checker แบบ command-line (ปกติ `npm run check` จะรันมัน) ที่เข้าใจไฟล์ `.svelte` แบบครบวงจร — รวมถึง expression ข้างใน markup ด้วย จับ prop type ที่ผิดหรือ typo ใน template ที่ `tsc` ธรรมดาจะพลาดไปเลยได้ | [Project & Tooling](/svelte/th/tooling-and-production/project-and-tooling/) |
| `svelte/events` `on` | function ที่ผูก listener แล้วคืน cleanup ให้ในการเรียกครั้งเดียว สำหรับกรณีที่ attribute ธรรมดาแสดงออกไม่ได้ — option `passive`/`once` หรือโค้ดที่ต้องอยู่ร่วมกับการ dispatch แบบ delegate ของ Svelte และการจัดการ `stopPropagation()` ของมันให้ถูกต้อง ใช้ข้างใน attachment หรือ `$effect` ไม่ใช่เป็น attribute ใน template | [Events & Attributes](/svelte/th/foundations/events-and-attributes/) |
| svelte-migrate | codemod CLI ทางการ (`npx svelte-migrate`) ที่ช่วย automate การ rewrite จาก Svelte 4 ไป 5 ส่วนใหญ่ — `export let` ไปเป็น `$props()`, `$:` ไปเป็น `$derived`/`$effect` — สำหรับ pattern แบบ legacy ชุดเดียวกับที่คอร์สนี้สอนให้จำได้ด้วยมือ ไม่ได้ถูกใช้จริงใน probe ของคอร์สนี้โดยตรง ให้มองว่านี่เป็นการชี้ทางที่ถูกต้อง มากกว่าข้อเท็จจริงที่พิสูจน์เองในคอร์ส | [Events & Attributes](/svelte/th/foundations/events-and-attributes/) |
| `svelte/reactivity` (`SvelteMap` …) | ตั้งแต่ Svelte 5.8 มี class reactive แบบ rune-native — `SvelteMap`, `SvelteSet`, `SvelteDate`, `SvelteURL`, `SvelteURLSearchParams`, `MediaQuery` — ที่ track การอ่านค่าและการเรียก method เหมือน `$state` โดยไม่มี `subscribe`/`$`/store contract เลย ต่างจาก `Map` ธรรมดาที่ห่อด้วย `$state` ตรงที่ `SvelteMap` ทำให้ `.set()`/`.delete()` เองก็ reactive ไม่ใช่แค่การแทนที่ค่าทั้งก้อน | [Built-in Stores](/svelte/th/state-and-stores/built-in-stores/) |
| `svelte/reactivity/window` | ค่า reactive แบบ rune-native สำหรับ global ของ browser (`innerWidth`, `scrollY`, `online`, …) แทนที่ listener แบบ resize/scroll/online ที่เขียนเอง มันอ่าน property จริงของ `window` ดังนั้น — เหมือนค่าที่มาจาก `window` ทุกตัว — ให้คาดหวังว่าอาจเกิด hydration mismatch ได้ตอน SSR ไม่ใช่ค่าฝั่ง server ที่ถูกต้องเสมอไป | [Built-in Stores](/svelte/th/state-and-stores/built-in-stores/) |

## T–V

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| `tick` | `await tick()` resolve เมื่อ batch ของ DOM update ที่ค้างอยู่ตอนนี้ถูก apply เสร็จแล้ว — สำหรับกรณีที่พบไม่บ่อยอย่างการวัดขนาด element หรือ focus ที่ input ที่เพิ่งโชว์ทันทีหลัง state เปลี่ยน ก่อนที่บรรทัดถัดไปจะรัน | [Lifecycle](/svelte/th/components/lifecycle/) |
| transition / `in:` / `out:` / `\|global` | `transition:` ทำ animation ให้ทั้งตอน element เข้ามาและออกไป; `in:`/`out:` ใส่ animation ต่างกันให้แต่ละด้านแยกจากกันได้ transition เป็นแบบ **local** เป็นค่า default — มันจะเล่นก็ต่อเมื่อ block ที่มันอยู่ตรง ๆ ถูกสร้างหรือทำลายเท่านั้น — และ `\|global` เปิดให้มันเล่นซ้ำเมื่อ ancestor block *ไหนก็ตาม* ถูกสร้างหรือทำลายแทน | [Transitions & Animations](/svelte/th/bindings-actions-transitions/transitions-and-animations/) |
| `untrack` | ให้ effect (หรือ derived) อ่านค่า reactive ได้โดย**ไม่**เพิ่มมันเป็น dependency ทำให้การเปลี่ยนค่านั้นอย่างเดียวไม่ trigger การรันใหม่ — import จาก `'svelte'` เป็นทางออกสำหรับกรณีที่พบไม่บ่อยที่การอ่านค่าบางอย่างต้องไม่ reactive ด้วยตัวมันเอง | [The $effect Rune](/svelte/th/reactivity/effect-rune/) |
| `use:enhance` | อัปเกรด action ของ `<form method="POST">` ธรรมดาให้เป็น AJAX submission แบบค่อยเป็นค่อยไป โดยไม่ต้องแก้ฝั่ง server เลย ใช้เปล่า ๆ ก็แค่หลีกเลี่ยงการ navigate ทั้งหน้าตอนสำเร็จ หรือถ้าใส่ callback (`use:enhance={fn}`) callback นั้นจะได้ควบคุมเต็มที่ผ่าน `update()`/`applyAction()` | [Forms & Actions](/svelte/th/sveltekit/forms-and-actions/) |
| `vite-plugin-svelte` | `@sveltejs/vite-plugin-svelte` ที่ `sv create` เชื่อมต่อให้อัตโนมัติ — ตัวที่รัน compiler ของ Svelte บนไฟล์ `.svelte` จริง ๆ ระหว่าง dev server และ build ของ Vite โค้ดวันต่อวันแทบไม่ต้องแตะมันโดยตรงเลย | [Project & Tooling](/svelte/th/tooling-and-production/project-and-tooling/) |

## W

| Term | ความหมาย | บทเรียน |
|------|---------|--------|
| writable derived (assignable `$derived`) | ตั้งแต่ Svelte 5.25 ค่า `$derived` ที่ประกาศด้วย `let` reassign ตรง ๆ ได้เลย (`likes += 1`) สำหรับ optimistic UI — ค่าที่ทับไว้จะเห็นผลทันทีและอยู่จนกว่า dependency จริงจะเปลี่ยนแล้วบังคับให้คำนวณใหม่ ตอนนั้นมันจะกลับไปเป็นค่า derived เหมือนเดิม ส่วน `const $derived` ยังคง reassign ไม่ได้ | [The $derived Rune](/svelte/th/reactivity/derived-rune/) |
