## Runes vs legacy mode

- ไฟล์นี้ผสม rune ใด ๆ (`$state`, `$derived`, `$effect`, `$props`) เข้ากับ `export let` หรือ `$:` แบบ top-level หรือไม่? ทั้งคู่เป็น **compile error แข็ง** ทันทีที่มี rune อยู่ ดู **[AI Bug Catalog](/svelte/th/reading-svelte/ai-bug-catalog/)** entry 2
- `<slot>` ถูกใช้ที่ไหนก็ตามในไฟล์ที่ใช้ rune อยู่แล้วหรือไม่? มันยัง compile ผ่าน (deprecation warning จริง ไม่ใช่ error) — ควรเป็น snippet ชื่อ `children`/named snippet แทน ดู entry 3
- ใช้ syntax แบบ directive `on:click` แทนที่จะเป็น property `onclick` ธรรมดาหรือไม่? ดู entry 1
- `createEventDispatcher` ถูกใช้ในโค้ดใหม่ทั้งที่ callback prop แบบ typed ธรรมดาจะง่ายกว่าและ idiomatic เท่ากันหรือไม่? ดู entry 4
- config ของ `eslint-plugin-svelte` เปิด `svelte/valid-compile` จริง ๆ หรือไม่ — rule ที่ทำให้ diagnostic ของ compiler เอง (deprecation/error) กลายเป็น lint output — หรือโปรเจกต์พึ่งพา `recommended` เพียงอย่างเดียวซึ่งไม่มี rule นี้รวมอยู่? ดู **[Verification Tools](/svelte/th/reading-svelte/verification-tools/)**

## State ownership

- `$effect` ที่ assign ให้ตัวแปร `$state` นี้ควรเป็น `$derived` แทนหรือไม่? ดู **[AI Bug Catalog](/svelte/th/reading-svelte/ai-bug-catalog/)** entry 5 และ 6
- มีค่าที่อ่านภายใน `setTimeout`/`Promise`/callback ที่รันหลังจาก `$effect`/`$derived` ที่ล้อมรอบจบรอบ synchronous ไปแล้ว โดยคาดหวังว่ามันยังเป็น tracked dependency หรือไม่? ดู entry 7
- ค่า `$state.raw` ถูก **mutate** ตรง ๆ (`.prop = x`, `.push(...)`) โดยคาดหวังว่า UI จะอัพเดต แทนที่จะ reassign หรือไม่? ดู entry 8
- body ของ `$derived` ทำอะไรมากกว่าการคำนวณและคืนค่า — เรียก API, `console.log`, push เข้า array ภายนอก หรือไม่? ดู entry 9
- มีค่าที่คำนวณครั้งเดียวภายใน `onMount` ทั้งที่ควรคำนวณใหม่ทุกครั้งที่ prop/state ที่มันพึ่งพาเปลี่ยนหรือไม่? ดู entry 10
- `$state` ที่ export จากโมดูล `.svelte.ts`/`.svelte.js` (แบบเปล่า หรือ class instance ที่ export ตรง ๆ) ถูก mutate ภายใน `load` function หรือ request handler หรือไม่ — ข้อมูลที่ควรสร้างใหม่ต่อคำขอแทน? ดู entry 11
- `$store` (รูปแบบย่อ prefix `$`) ถูกอ่านที่ไหนก็ตามนอกเหนือจาก top level ของ component หรือโมดูลหรือไม่? ดู entry 12
- `get(store)` ถูกเรียกซ้ำ ๆ ภายใน loop, `$effect` ที่รันถี่, หรือทุกครั้งที่พิมพ์ แทนที่จะ subscribe ครั้งเดียวหรือไม่? ดู entry 13
- store (`writable`/`readable`/`derived`) ถูกห่อด้วย `$state` เป็นครั้งที่สอง ผสมสองระบบ reactivity ที่ไม่ track อะไรที่มีประโยชน์ร่วมกันเลยหรือไม่? ดู entry 14

## Props, bindings และ snippets

- parent ทำ `<Child bind:value={x} />` ทั้งที่ `Child` ไม่เคยประกาศ `value = $bindable()` หรือไม่? ดู **[AI Bug Catalog](/svelte/th/reading-svelte/ai-bug-catalog/)** entry 15
- `{#snippet name(...)}` ทุกตัวในไฟล์ถูก render จริงที่ไหนสักแห่งด้วย `{@render name(...)}` ที่จับคู่กัน — ไม่เคยถูกทิ้งไว้ ไม่เคยถูกเรียกเป็น `{name(...)}` เปล่า ๆ หรือไม่? ดู entry 16 และ 17
- `bind:value` บน input ชนิด `type="number"`/`type="range"` ถูกปฏิบัติเหมือน string ที่ไหนก็ตามในโค้ดถัดไป (`.trim()`, `.length`, การต่อ string) หรือไม่? ดู entry 18
- snippet prop ถูก type ด้วย `Snippet<[T]>` เมื่อมัน parameter หรือไม่ เพื่อให้รูปร่างที่ไม่ตรงกันเป็น `svelte-check` error ตอน compile แทนที่จะเป็นความประหลาดใจตอนรันจริง? ดู **[Passing UI & Children](/svelte/th/components/passing-ui-and-children/)**

## Event และ DOM

- `use:action={value}` สมมติว่า `value` อัพเดต DOM อัตโนมัติ โดยไม่มี method `update` ประกาศไว้บน action หรือไม่ — หรือควรเป็น attachment ของ Svelte 5.29+ แทน? ดู **[AI Bug Catalog](/svelte/th/reading-svelte/ai-bug-catalog/)** entry 19
- `addEventListener` ที่ผูกมือระหว่าง DOM root กับ `onclick` ของ Svelte เรียก `stopPropagation()` ทำลาย delegated handler เงียบ ๆ หรือไม่? ดู entry 20
- โค้ดที่ต้องการ semantics `passive`/`once` ใช้ฟังก์ชัน `on` จาก `svelte/events` แทน attribute ธรรมดาที่แสดง option เหล่านั้นไม่ได้หรือไม่?
- `use:` ถูกพยายามใช้บน component (`<MyComponent use:foo />`) หรือไม่? มันใช้ได้แค่กับ DOM element เท่านั้น — attachment คือสิ่งที่เทียบเท่าที่ใช้กับ component ได้

## ขอบเขตของ SvelteKit

- `try/catch` ห่อการเรียก `redirect()`/`error()` โดยไม่ตรวจ `isRedirect`/`isHttpError` ก่อนถือว่า catch คือความล้มเหลวจริงหรือไม่? ดู **[AI Bug Catalog](/svelte/th/reading-svelte/ai-bug-catalog/)** entry 22
- `+page.js` (universal load) import `$env/static/private`, `$env/dynamic/private`, หรือโมดูล server-only อื่นใดหรือไม่? ดู entry 24
- form action คืนค่า object ธรรมดาตอน validation ล้มเหลว แทนที่จะเป็น `fail(status, data)` หรือไม่? ดู entry 25
- `load` function `await` ค่าที่การวาดครั้งแรกไม่ต้องใช้ แทนที่จะคืน promise แบบไม่ await ให้ `{#await}` stream หรือไม่? ดู entry 23
- โค้ด import `page`/`navigating`/`updated` จาก `$app/stores` แทนที่จะเป็น `$app/state` ที่ไม่ deprecated หรือไม่? ดู entry 21
- `event.locals` ถูกใช้ที่ไหนก็ตามโดยไม่มี interface `App.Locals` ที่จับคู่กันประกาศไว้ใน `src/app.d.ts` หรือไม่?

## Keys, transitions และ boundaries

- `{#each}` ทุกตัวเหนือลิสต์ของ component (หรือ element ที่มี local state ที่มีความหมาย) ใช้ key ที่มั่นคงมาจากข้อมูล — ไม่ใช่ array index ไม่เคยละไว้เลยหรือไม่? ดู **[AI Bug Catalog](/svelte/th/reading-svelte/ai-bug-catalog/)** entry 26
- `reset()` ถูกเรียกแบบ synchronous ภายใน callback `<svelte:boundary onerror>` แทนที่จะเรียกจาก action แยกต่างหากหรือหลัง `await tick()` หรือไม่? ดู entry 28
- `await` ปรากฏตรง ๆ ในเทมเพลตหรือ `$derived` โดยไม่มี `compilerOptions.experimental.async: true` ตั้งไว้ที่ไหนเลยในโปรเจกต์หรือไม่? ดู entry 27
- โค้ดสมมติว่า snippet `<svelte:boundary pending>` จะแสดงสำหรับ**ทุก**การอัพเดตแบบ async รวมถึงตัวที่มาหลังการวาดครั้งแรก — ทั้งที่มีแค่ `$effect.pending()` เท่านั้นที่ครอบคลุมกรณีนั้นหรือไม่?
- มี `<svelte:boundary>` ล้อมรอบ subtree ที่ throw ได้จริงตอน render หรือใน effect พร้อม `failed`/`onerror` จริง — หรือ widget ที่พังตัวเดียวเสี่ยงทำให้ทั้งหน้า unmount หรือไม่?
