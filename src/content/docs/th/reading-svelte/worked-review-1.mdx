## ฟีเจอร์นี้คืออะไร

โจทย์ที่ให้ AI คือ *"สร้าง todo list ที่มี add/rename/toggle, ประวัติ undo, แถบตัวกรอง, badge นับจำนวนที่เสร็จแล้ว และแผงสถิติที่แสดงจำนวนที่ยังไม่เสร็จ"* ผลลัพธ์ด้านล่างคือแบบร่างที่ AI มักส่งกลับมาสำหรับฟีเจอร์ Svelte 5 เล็ก ๆ — ทุกไฟล์ใช้ `$props()`/`$state`/`$derived` อยู่ที่ใดที่หนึ่ง ทำให้ทั้งโปรเจกต์ (ถูกบังคับเข้า runes mode โดย `vite.config.ts` ของคอร์สนี้เอง เหมือนโปรเจกต์ที่ AI สร้างส่วนใหญ่ตั้งแต่ Svelte 5.0) ปฏิบัติต่อทุกไฟล์ว่าเป็นโค้ดโหมด runes อ่านตาม[ลำดับการอ่าน](/svelte/th/reading-svelte/)ของโมดูลนี้: runes เทียบกับ legacy mode ก่อน แล้วดูว่าใครเป็นเจ้าของ state แต่ละก้อน แล้วก็ props/bindings/snippets แล้วก็ event กับ DOM แล้วก็ key โค้ดนี้มี **บั๊กจริง 6 จุด** จาก 4 หมวดที่ต่างกัน และ 2 จุดในนั้นเป็น compile error จริงที่ `svelte-check` จับได้ทันที — อีก 4 จุดคอมไพล์ผ่านสะอาดแต่พฤติกรรมผิด

```svelte
<!-- src/lib/todos/TodoApp.svelte — as generated -->
<script lang="ts">
  import type { Filter, Todo } from './types';
  import TodoList from './TodoList.svelte';
  import TodoStats from './TodoStats.svelte';
  import CompletedBadge from './CompletedBadge.svelte';

  let nextId = 1;
  let todos = $state<Todo[]>([]);
  let filter = $state<Filter>('all');
  let history = $state<Todo[][]>([]);

  function pushHistory() {
    history.push(todos.map((t) => ({ ...t })));
  }
  function addTodo(text: string) {
    pushHistory();
    todos.push({ id: String(nextId++), text, done: false });
  }
  function toggleTodo(id: string) {
    pushHistory();
    const t = todos.find((t) => t.id === id);
    if (t) t.done = !t.done;
  }
  function renameTodo(id: string, text: string) {
    pushHistory();
    const t = todos.find((t) => t.id === id);
    if (t) t.text = text;
  }
  function undo() {
    const prev = history.pop();
    if (prev) todos = prev;
  }

  let visible = $derived(
    todos.filter((t) => (filter === 'active' ? !t.done : filter === 'completed' ? t.done : true)),
  );
</script>

{#snippet emptyState()}
  <p>No todos match this filter.</p>
{/snippet}

<div>
  <button onclick={() => addTodo(`Task ${nextId}`)}>Add</button>
  <button onclick={undo} disabled={history.length === 0}>Undo</button>
  <div role="group">
    {#each ['all', 'active', 'completed'] as const as f}
      <button aria-pressed={filter === f} on:click={() => (filter = f)}>{f}</button>
    {/each}
  </div>

  <TodoList todos={visible} onToggle={toggleTodo} onRename={renameTodo} />

  <TodoStats {todos} />
  <CompletedBadge {todos} />
</div>
```

## ไล่รีวิวทีละบั๊ก

### Runes เทียบกับ legacy mode: `export let` กับ `$:` ปนอยู่ในไฟล์ runes

`TodoStats` เอา `export let`/`$:` ซึ่งเป็นกลไก reactivity ของ Svelte 4 มาปนกับโปรเจกต์ที่อยู่ใน runes mode ทุกที่ (รูนไหนก็ตามที่โผล่ในไฟล์ — หรืออย่างที่นี่ คือ compiler option `runes: true` ระดับโปรเจกต์ — ทำให้ไฟล์นั้นเข้า runes mode) นี่คือรูปแบบบั๊ก Svelte ที่ AI สร้างพบบ่อยที่สุด และไม่ใช่ warning เบา ๆ:

<SpotTheBug code={`export let todos: Todo[];
$: activeCount = todos.filter((t) => !t.done).length;`}>
ทั้งสองบรรทัดเป็น compile error จริงทันทีที่ไฟล์อยู่ใน runes mode — ไม่ใช่ "ไม่คาดคิดแต่ยอมให้ผ่าน" แต่เป็น `svelte-check` error จริงที่บล็อกการคอมไพล์:

```text
Error: Cannot use `export let` in runes mode — use `$props()` instead
https://svelte.dev/e/legacy_export_invalid
```

พอลบแค่บรรทัด `export let` แล้วเช็คใหม่ จะเห็นว่ากลไก legacy อีกตัว (`$:`) ก็เป็น error จริงแยกต่างหากของมันเองด้วย — compiler ไม่ได้หยุดแค่ "เจอ legacy หนึ่งแบบพอแล้ว" แต่ละแบบถูกเช็คและปฏิเสธแยกกัน:

```text
Error: `$:` is not allowed in runes mode, use `$derived` or `$effect` instead
https://svelte.dev/e/legacy_reactive_statement_invalid
```

คู่นี้ถูกพิสูจน์ครบวงจรอยู่แล้ว พร้อมข้อความจริงที่ `compile()` throw ออกมา ในบท [Events & Attributes](/svelte/th/foundations/events-and-attributes/) — SpotTheBug นี้แค่ reproduce กับไฟล์ของฟีเจอร์นี้เอง วิธีแก้คือ `$props()` กับ `$derived` ตามที่แสดงด้านล่าง
</SpotTheBug>

### ใครเป็นเจ้าของ state นี้: `$effect` ที่เขียนค่าที่ `$derived` ควรเป็นเจ้าของ

`CompletedBadge` คำนวณ `doneCount` — ค่าที่ derive ได้เต็มที่จาก `todos` — โดยเขียนมันลง `$state` แยกต่างหากจากข้างใน `$effect`

<SpotTheBug code={`let doneCount = $state(0);
$effect(() => {
  doneCount = todos.filter((t) => t.done).length;
});`}>
โค้ดนี้คอมไพล์ผ่านสะอาดและดูถูกต้องทุก render ที่เช็คด้วยตา บท [$effect Rune](/svelte/th/reactivity/effect-rune/) พิสูจน์ต้นทุนที่เป็นรูปธรรมด้วย test จริง: ค่าที่ mirror ผ่าน effect จะ**ค้าง (stale)** จริง ๆ ในช่วงเวลาระหว่างการเขียนที่กระตุ้นมันกับ flush รอบถัดไป ซึ่ง `$derived` ไม่มีช่วงเวลาแบบนี้เลย reproduce กับ pattern นี้ตรง ๆ:

```text
✓ CompletedBadge: re-syncs doneCount through a whole extra $effect commit on every todos change
✓ bare-state proof: mirroring a derived value via $effect lags one flush behind $derived

Test Files  1 passed (1)
     Tests  2 passed (2)
```

วิธีแก้คือลบ `$effect` กับตัวแปร `$state` แยกทิ้งไปเลย: `let doneCount = $derived(todos.filter((t) => t.done).length);` คำนวณใหม่ทันทีที่ถูกอ่าน ไม่มีการค้าง ไม่มีที่ที่สองให้ค่านี้อาศัยอยู่
</SpotTheBug>

### ใครเป็นเจ้าของ state นี้: mirror prop เข้า `$state`

`EditableLabel` copy prop `text` เข้า `draft` ตอน mount เพื่อให้ input มีที่แก้ไขในเครื่องก่อน save

<SpotTheBug code={`let { text, onSave } = $props();
let draft = $state(text); // mirrors the prop once, at mount`}>
`$state(text)` อ่าน `text` แค่ครั้งเดียว — ณ ตอนที่บรรทัดนี้รัน — แล้วไม่อ่านอีกเลย `svelte-check` เองก็เตือนเรื่องนี้ให้โดยไม่ต้องถาม:

```text
Warn: This reference only captures the initial value of `text`. Did you mean to reference it inside a closure instead?
https://svelte.dev/e/state_referenced_locally
```

แต่ warning นี้ง่ายที่จะมองข้ามว่าเป็นแค่ noise เลยต้องพิสูจน์พฤติกรรมจริง: ถ้า `text` เปลี่ยนจาก**ภายนอก** component นี้ทีหลัง — undo ที่คืนค่าก่อนหน้าของ todo ตัวเดียวกันเป๊ะ ๆ คือ trigger ที่สมจริงที่สุดในกรณีนี้ — `draft` จะไม่ตามไปด้วย

```text
✓ EditableLabelBad: does not resync draft when the text prop changes from outside (e.g. undo)

Test Files  1 passed (1)
     Tests  1 passed (1)
```

วิธีแก้คือยังคง local edit-buffer ไว้ (เป็นความจำเป็นด้าน design จริง — bind ตรงเข้า prop ที่ immutable ระหว่างพิมพ์ไม่ได้) แต่ resync มันทุกครั้งที่ค่าต้นทางเปลี่ยน และปิด warning อย่างตรงไปตรงมาด้วย `untrack` (แสดงในโค้ดที่แก้ไขแล้วด้านล่าง) แทนที่จะเมินมันไป
</SpotTheBug>

### Props, bindings, และ snippets: `{#snippet}` ที่ไม่เคยถูก `{@render}`

`TodoApp` ประกาศ snippet ชื่อ `emptyState` ไว้สำหรับตอนที่ list ที่กรองแล้วว่างเปล่า แต่ไม่เคย render มันที่ไหนเลยจริง ๆ

<SpotTheBug code={`{#snippet emptyState()}
  <p>No todos match this filter.</p>
{/snippet}

<!-- ...TodoList is always rendered, unconditionally, regardless of visible.length -->`}>
`{#snippet}` block เป็นค่า (value) ไม่ใช่ declaration ที่มีผลข้างเคียง — แค่ประกาศมันไม่ทำอะไรเลย มีแค่ `{@render name()}` เท่านั้นที่เอา markup ของมันไปวางบนหน้า ไม่มีอะไรตรงนี้ compile ไม่ผ่านหรือ warning เลย: snippet เป็นแค่ dead code และกรณี filter ว่างเปล่าก็ render `<ul>` ว่าง ๆ ออกมาโดยไม่มีคำอธิบายใด ๆ

```text
✓ EmptyStateBad: never shows the empty-state snippet because it is declared but never {@render}ed

Test Files  1 passed (1)
     Tests  1 passed (1)
```

วิธีแก้คือ `{#if visible.length === 0}{@render emptyState()}{:else}...{/if}` ครอบสองกิ่งนี้ไว้ ซึ่งพิสูจน์แล้วในบท [Snippets & Render](/svelte/th/components/snippets-and-render/) ว่าเป็น contract จริงที่ชื่อของ snippet แบกอยู่
</SpotTheBug>

### Event กับ DOM: `on:click` แทนที่จะเป็น `onclick`

ปุ่มตัวกรองใช้ syntax event-directive แบบ Svelte 4

<SpotTheBug code={`<button aria-pressed={filter === f} on:click={() => (filter = f)}>{f}</button>`}>
ต่างจาก `export let`/`$:` นี่คือ syntax จริงที่ใช้งานได้ ซึ่ง compiler ยังจำได้และแปลงให้ถูกต้อง — มันลดระดับลงเป็นแค่ deprecation warning ไม่ใช่ error:

```text
Warn: Using `on:click` to listen to the click event is deprecated. Use the event attribute `onclick` instead
https://svelte.dev/e/event_directive_deprecated
```

วิธีแก้คือ `onclick` ซึ่งเป็น property ธรรมดาเหมือน event handler อื่น ๆ ของ Svelte 5 ทั้งหมด พิสูจน์แล้วพร้อมตารางการจดจำ legacy แบบเต็มในบท [Events & Attributes](/svelte/th/foundations/events-and-attributes/)
</SpotTheBug>

### Key กับ identity: `{#each}` ไม่มี key ที่มี child เก็บ state

`TodoList` วน `todos` โดยไม่มี key `(todo.id)` และแต่ละ `TodoItem` ก็เก็บ state `selected` ของตัวเอง — local ล้วน ๆ ไม่ผูกกับอะไรในข้อมูลเลย

<SpotTheBug code={`{#each todos as todo}
  <TodoItem {todo} {onToggle} {onRename} />
{/each}`}>
ถ้าไม่มี key, Svelte จะใช้ component instance เดิม — พร้อม local state ที่มันถืออยู่ — ของแต่ละ**ตำแหน่ง**ใน list ซ้ำ ไม่ใช่ตาม identity ของ todo ตราบใดที่ list ไม่เคยเปลี่ยนลำดับ โค้ดนี้ก็ดูปกติดีทุกอย่าง ทันทีที่มีรายการถูกแทรกไว้หน้าสุด — ซึ่งเป็นสิ่งที่ "Undo" และประวัติของแอปนี้เองทำได้พอดี — state ภายในของแถว**เก่า** (checkbox `selected` ของมัน) จะยังติดอยู่กับรายการที่บังเอิญมาอยู่ตำแหน่งเดิมนั้น

```text
✓ TodoListBad (keyless each): bleeds per-row selection to the WRONG row after prepending an item

Test Files  1 passed (1)
     Tests  1 passed (1)
```

วิธีแก้คือ `{#each todos as todo (todo.id)}` — id ที่คงที่จากข้อมูล ไม่ใช่ตำแหน่งปัจจุบันของแถว
</SpotTheBug>

<script lang="ts">

  import TodoList from './TodoList.svelte';
  import TodoStats from './TodoStats.svelte';
  import CompletedBadge from './CompletedBadge.svelte';

  let nextId = 1;
  let todos = $state<Todo[]>([]);
  let filter = $state<Filter>('all');
  let history = $state<Todo[][]>([]);

  function pushHistory() {
    history.push(todos.map((t) => ({ ...t })));
  }
  function addTodo(text: string) {
    pushHistory();
    todos.push({ id: String(nextId++), text, done: false });
  }
  function toggleTodo(id: string) {
    pushHistory();
    const t = todos.find((t) => t.id === id);
    if (t) t.done = !t.done;
  }
  function renameTodo(id: string, text: string) {
    pushHistory();
    const t = todos.find((t) => t.id === id);
    if (t) t.text = text;
  }
  function undo() {
    const prev = history.pop();
    if (prev) todos = prev;
  }

  let visible = $derived(
    todos.filter((t) => (filter === 'active' ? !t.done : filter === 'completed' ? t.done : true)),
  );
</script>

{#snippet emptyState()}
  <p data-testid="empty">No todos match this filter.</p>
{/snippet}

<div>
  <button onclick={() => addTodo(`Task ${nextId}`)}>Add</button>
  <button onclick={undo} disabled={history.length === 0}>Undo</button>
  <div role="group">
    <!-- FIX (events & DOM): onclick, not the deprecated on:click. -->
    {#each ['all', 'active', 'completed'] as const as f}
      <button aria-pressed={filter === f} onclick={() => (filter = f)}>{f}</button>
    {/each}
  </div>

  <!-- FIX (props/bindings/snippets): the empty-state snippet is now actually rendered. -->
  {#if visible.length === 0}
    {@render emptyState()}
  {:else}
    <TodoList todos={visible} onToggle={toggleTodo} onRename={renameTodo} />
  {/if}

  <TodoStats {todos} />
  <CompletedBadge {todos} />
</div>

## สิ่งที่เปลี่ยนและเหตุผล

| # | บั๊ก | หมวด | วิธีแก้ |
|---|---|---|---|
| 1 | `export let`/`$:` ปนอยู่ในไฟล์ runes mode | Runes vs legacy | `$props()` + `$derived` — ทั้งสอง legacy form เป็น compile error จริง ไม่ใช่ warning |
| 2 | `$effect` เขียน `doneCount` แทนที่จะ derive มัน | State ownership | ลบ `$effect` กับ `$state` แยกทิ้ง ใช้ `$derived` |
| 3 | `$state(text)` mirror prop ครั้งเดียว ไม่เคย resync | State ownership | resync ผ่าน `$effect`; ปิด warning (ที่ถูกต้อง) ด้วย `untrack` |
| 4 | `{#snippet emptyState}` ประกาศไว้ แต่ไม่เคย `{@render}` | Props/bindings/snippets | `{@render emptyState()}` ใน `{#if visible.length === 0}` |
| 5 | `on:click` บนปุ่มตัวกรอง | Events & DOM | `onclick` — syntax เดียวกัน แค่ deprecated แต่ยังทำงาน |
| 6 | `{#each todos as todo}` ไม่มี key ที่มี `TodoItem` เก็บ state | Keys & identity | `{#each todos as todo (todo.id)}` |

## Mental Model

สองในหกบั๊กนี้ไม่ถึงขั้น runtime เลยด้วยซ้ำ — `svelte-check` ปฏิเสธไม่ให้คอมไพล์ เพราะ runes mode กับ legacy mode เป็นสอง compiler pass ที่แยกกันและรวมกันไม่ได้ อีกสี่จุดที่เหลือคอมไพล์ผ่านสะอาดทั้งหมดและดูถูกต้องใน render เดียว: ค่าที่ mirror ผ่าน effect จะผิดในช่วงเวลาที่การเทสด้วยมือส่วนใหญ่ไม่มีทางเจอ, prop ที่ mirror ไว้จะผิดก็ต่อเมื่อมีการเปลี่ยนแปลงจากภายนอกครั้งที่สอง, snippet ที่ตายจะผิดก็ต่อเมื่อ list บังเอิญว่างเปล่า, list ที่ไม่มี key จะผิดก็ต่อเมื่อมีการเรียงลำดับใหม่ การอ่านโค้ดครั้งเดียวพิสูจน์อะไรไม่ได้เลยสำหรับสี่จุดหลัง มีแต่การรันจริงเท่านั้น — `svelte-check` ผ่านจริงบวก `vitest` ที่รันจริงกับการ reorder และการเปลี่ยน prop ปลอม ๆ — ถึงจะพิสูจน์ได้

## ความเข้าใจผิดที่พบบ่อย

- **"ถ้าอยู่ในไฟล์ `.svelte` เดียวกัน `export let` กับ `$state` ปนกันได้ Svelte จะจัดการเอง"** พิสูจน์แล้วว่าผิด สองครั้งด้วยข้อความ error จริง: ทันทีที่รูนไหนก็ตามโผล่ในไฟล์ (หรือโปรเจกต์บังคับ runes mode) `export let` กับ `$:` เป็น compile error จริง ไม่ใช่ warning แบบ "เลือกเอาอันเดียว"
- **"ตัวแปร `$state` ที่ initialize จาก prop จะ sync กับ prop นั้นตลอดไป"** พิสูจน์แล้วว่าผิด: `$state(text)` อ่าน `text` แค่ครั้งเดียวเป๊ะ ๆ compiler ของ Svelte เองยังเตือนบรรทัดนี้ตรง ๆ — `state_referenced_locally` — ซึ่งควรเชื่อมันมากกว่าจะมองข้าม
- **"แค่ประกาศ `{#snippet}` ก็พอทำให้มันปรากฏแล้ว"** snippet เป็นค่า (value) มีแค่ `{@render name()}` เท่านั้นที่เอามันไปวางบนหน้า snippet ที่ไม่ถูก render ไม่สร้าง error, warning, หรือ console output ใด ๆ เลย
- **"list `key` ที่หายไปมีผลแค่เรื่อง performance"** พิสูจน์แล้วว่าผิดด้วย reorder test: ถ้าไม่มี key, local state ของแถวที่ไม่เกี่ยวข้อง (ในที่นี้คือ checkbox การเลือก) จะตาม*ตำแหน่ง*ของ list ไม่ใช่ข้อมูล — เป็นบั๊กด้าน correctness ไม่ใช่ performance
