## ฟีเจอร์นี้คืออะไร

โจทย์ที่ให้ AI คือ *"สร้างแดชบอร์ดที่มี slider สำหรับกรองข้อมูลตามเกณฑ์ (threshold), chart widget ที่โชว์จุดข้อมูลสูงสุด, tooltip บน slider, สถิติ 'ยอดรวม' แบบ async, และการตั้งค่า legend ที่ผู้ใช้สลับได้"* แบบร่างนี้พึ่งพา 4 ฟีเจอร์ของ Svelte 5 ที่ AI มักหยิบมาใช้บ่อย ๆ — `bind:`, action `use:`, `$state.raw`, และ `await` ในเทมเพลต — แล้วทำ*สัญญา (contract)*ของแต่ละตัวผิดไปนิดหน่อย อ่านตาม[ลำดับการอ่าน](/svelte/th/reading-svelte/)ของโมดูลนี้: หลังจาก runes เทียบกับ legacy และเจ้าของ state (รีวิวก่อนหน้านี้) สองขั้นถัดไปคือ props/bindings/snippets และ event/DOM — ซึ่งเป็นที่อยู่ของ 4 ใน **บั๊กจริง 5 จุด** นี้พอดี สองจุดเป็น compile error จริง

## ไล่รีวิวทีละบั๊ก

### Props, bindings, snippets: `bind:` ไปที่ prop ที่ไม่ใช่ `$bindable`

`RangeFilter` ไม่เคยให้ prop `min` ของมัน opt-in เป็น two-way binding แต่ `Dashboard` กลับ bind เข้าไปเฉย ๆ

<SpotTheBug code={`<!-- RangeFilter.svelte -->
let { min }: { min: number } = $props();

<!-- Dashboard.svelte -->
<RangeFilter bind:min={threshold} />`}>
prop ไหลทางเดียวเสมอ เว้นแต่ child จะเปิดช่องทาง two-way ให้ชัดเจนด้วย `$bindable()` นี่คือ `svelte-check` error จริงที่บอกวิธีแก้ตรง ๆ — ไม่ใช่ no-op เงียบ ๆ:

```text
Error: Cannot use 'bind:' with this property. It is declared as non-bindable inside the component.
To mark a property as bindable: 'let { min = $bindable() } = $props()' (ts)
```

วิธีแก้คือ `let { min = $bindable() }: { min: number } = $props();` ข้างใน `RangeFilter` — พิสูจน์แล้วในบท [Bindings](/svelte/th/bindings-actions-transitions/bindings/) ว่าจำเป็นก่อนที่ `bind:` ไปยัง prop ของ component จะถูกกฎหมาย
</SpotTheBug>

### Event กับ DOM: `use:` action ที่ไม่เคยรันซ้ำ

`tooltip` ตั้ง `node.title` แค่ครั้งเดียวตอน mount จาก `text` ที่เป็นอยู่ ณ ตอนนั้น

<SpotTheBug code={`export function tooltip(node: HTMLElement, text: string) {
  node.title = text; // set once at mount
}`}>
function body ของ action รันแค่ครั้งเดียวเป๊ะ ๆ ตอน element mount นอกจากมันจะ return method `update(newArg)` ไม่งั้น Svelte ไม่มีทางรู้เลยว่า argument*เปลี่ยนได้*ด้วยซ้ำ — และ `visible.length` ตรงนี้เปลี่ยนทุกครั้งที่ slider threshold ขยับ

```text
✓ TooltipButtonBad: never updates node.title after the text prop changes — no update() on the action

Test Files  1 passed (1)
     Tests  1 passed (1)
```

วิธีแก้คือ return `{ update(newText) { node.title = newText; } }` พิสูจน์แล้วในบท [Actions](/svelte/th/bindings-actions-transitions/actions/) ว่าเป็นสิ่งเดียวที่ทำให้ argument ของ action reactive จริง (attachment `@attach` ได้สิ่งนี้มาฟรี ๆ รันซ้ำทุกครั้งที่ค่า reactive ที่มันอ่านเปลี่ยน ซึ่งเป็นเหตุผลที่บท Actions ของคอร์สนี้แนะนำ attachment สำหรับโค้ดใหม่ — `use:` ยังคงไว้สำหรับ interop กับ library)
</SpotTheBug>

### Props, bindings, snippets: `await` ในเทมเพลตโดยไม่มี `experimental.async`

`AsyncStat` await ตรง ๆ ใน template expression

<SpotTheBug code={`<p>Total: {await load()}</p>`}>
`await` ในเทมเพลต, ใน `$derived`, หรือระดับบนสุดของ component เป็น compile error จริงเว้นแต่โปรเจกต์จะเปิด compiler flag แบบทดลอง (experimental) — โค้ดที่ AI สร้างส่วนใหญ่ไม่เคยพูดถึงมันเลย เพราะมันเกิดก่อนฟีเจอร์นี้จะมี:

```text
Error: Cannot use `await` in deriveds and template expressions, or at the top level of a component, unless the `experimental.async` compiler option is `true`
https://svelte.dev/e/experimental_async
```

พอเปิด `experimental.async: true` (`vite.config.ts` ของคอร์สนี้เองเปิดไว้ทั้งโปรเจกต์อยู่แล้ว เหมือนที่บท [Async Svelte](/svelte/th/reactivity/async-svelte/) พิสูจน์ไว้) source เดียวกันเป๊ะก็คอมไพล์ผ่านโดยไม่มี error หรือ warning เลย วิธีแก้ตรงนี้ไม่ใช่การแก้ component เลย — แต่คือการทำให้แน่ใจว่าโปรเจกต์ที่ AI สร้างโค้ดนี้ให้เปิด flag ไว้จริง ๆ แล้วครอบ await ด้วย `<svelte:boundary pending>` สำหรับ loading UI (แสดงในโค้ดที่แก้ไขแล้ว)
</SpotTheBug>

### Key, transition, boundary: ไม่มี `<svelte:boundary>` ครอบ widget ที่ throw

`ChartWidget` throw เมื่อ `points` ว่างเปล่า (`Math.max()` ของอาเรย์ว่างคือ `-Infinity` ไม่มี point ไหน value เท่านั้น เลย `.find()` ได้ `undefined` แล้ว `top.label` ก็ throw) `Dashboard` render มันโดยไม่มี boundary เลย

<SpotTheBug code={`<h2>Dashboard</h2>
<ChartWidget points={visible} />
<!-- no <svelte:boundary> anywhere -->`}>
โดย default, error ที่ถูก throw ระหว่าง render จะ unmount **root ที่ใกล้ที่สุดทั้งก้อน** ไม่ใช่แค่ widget ที่พัง — ผลการกรองที่ว่างเปล่า (สถานะปกติที่เข้าถึงได้จริง ไม่ใช่ edge case) จะดึงทั้งแดชบอร์ดลงไปด้วย รวมถึง slider กับ async stat ที่ไม่เกี่ยวอะไรกับกราฟเลย

```text
✓ DashboardNoBoundaryBad: an empty points array crashes the WHOLE dashboard, uncaught

Test Files  1 passed (1)
     Tests  1 passed (1)
```

วิธีแก้ พิสูจน์แล้วในบท [Lifecycle](/svelte/th/components/lifecycle/) ที่ครอบคลุม `<svelte:boundary>` แบบเต็ม คือครอบแค่ `ChartWidget` ด้วย boundary ที่มี `{#snippet failed}` — ส่วนที่เหลือของแดชบอร์ดรอดไปตามปกติ
</SpotTheBug>

### เจ้าของ state: `$state.raw` ถูก mutate แทนที่จะ reassign

`ChartSettings` mutate property ของ object `$state.raw` ตรง ๆ

<SpotTheBug code={`let options = $state.raw({ color: 'teal', showLegend: true });
function toggleLegend() {
  options.showLegend = !options.showLegend; // mutation
}`}>
`$state.raw` ปฏิเสธ Proxy แบบ deep-reactive — พิสูจน์แล้วในบท [$state Rune](/svelte/th/reactivity/state-rune/) ว่ามีแค่การ**reassign ทั้ง cell**เท่านั้นที่นับเป็นการเขียน การ mutate เนื้อหาข้างในเปลี่ยนข้อมูลในหน่วยความจำจริง แต่ไม่แจ้งอะไรเลย UI จึงไม่อัปเดตเงียบ ๆ:

```text
✓ ChartSettingsBad: mutating $state.raw in place does not trigger a re-render

Test Files  1 passed (1)
     Tests  1 passed (1)
```

วิธีแก้คือ `options = { ...options, showLegend: !options.showLegend }` — object ใหม่เอี่ยม ซึ่ง `$state.raw` ตอบสนองด้วย
</SpotTheBug>

import { describe, it, expect, vi } from 'vitest';
import { render, screen, fireEvent } from '@testing-library/svelte';

import ChartWidget from './ChartWidget.svelte';
import ChartSettings from './ChartSettings.svelte';
import AsyncStat from './AsyncStat.svelte';

describe('ThresholdSlider (fixed): $bindable() lets the parent bind: to it', () => {
  it('a slider change propagates back to the bound parent variable', async () => {
    let min = $state(0);
    render(ThresholdSlider, { props: { get min() { return min; }, set min(v) { min = v; } } });
    await fireEvent.input(screen.getByTestId('threshold'), { target: { value: '42' } });
    expect(min).toBe(42);
  });
});

describe('tooltip action (fixed): update() re-runs when the argument changes', () => {
  it('node.title tracks the latest text via update()', async () => {
    const { tooltip } = await import('./tooltip');
    const node = document.createElement('div');
    const action = tooltip(node, 'first');
    expect(node.title).toBe('first');
    action?.update?.('second');
    expect(node.title).toBe('second');
  });
});

describe('ChartSettings (fixed): reassigning $state.raw triggers a re-render', () => {
  it('toggling legend flips the rendered text', async () => {
    render(ChartSettings);
    expect(screen.getByTestId('legend').textContent).toBe('legend on');
    await fireEvent.click(screen.getByTestId('toggle'));
    expect(screen.getByTestId('legend').textContent).toBe('legend off');
  });
});

describe('ChartWidget inside a <svelte:boundary>: contained, not fatal', () => {
  it('an empty points array still throws (the widget itself is unchanged)', () => {
    expect(() => render(ChartWidget, { props: { points: [] } })).toThrow();
  });
});

describe('AsyncStat (fixed): await in the template, gated by experimental.async', () => {
  it('shows the pending snippet, then the resolved total', async () => {
    let resolveLoad!: (v: number) => void;

  });
});

## Mental Model

ทุกบั๊กในรีวิวนี้คือ**การละเมิดสัญญา (contract)** ไม่ใช่ความผิดพลาดด้าน syntax: `bind:` สมมติว่า child opt-in แล้ว, `use:` สมมติว่า action รันซ้ำเหมือน prop reactive, `await` ในเทมเพลตสมมติว่า experimental flag เปิดอยู่ และการ mutate `$state.raw` สมมติว่ามันได้ reactivity แบบเดียวกับ `$state` มาฟรี ๆ สองในห้าสัญญาถูกบังคับโดย compiler เอง (bind, await) อีกสามที่เหลือเงียบสนิท มีแค่ probe ที่รันจริงเท่านั้น — reorder จริง, นับ re-render จริง, throw จริง — ถึงจะเผยว่าสัญญาไหนถูกละเมิด

## ความเข้าใจผิดที่พบบ่อย

- **"`bind:` ใช้ได้เสมอถ้า child มี prop ชื่อนั้น"** พิสูจน์แล้วว่าผิดด้วย `svelte-check` error จริง: prop ไหลทางเดียวโดย default และ `bind:` ไปยังมันจะถูกปฏิเสธเว้นแต่ child จะเขียน `$bindable()`
- **"argument ของ `use:` action reactive อัตโนมัติเหมือน prop"** พิสูจน์แล้วว่าผิด: ถ้าไม่มี method `update()` function body ของ action จะรันแค่ครั้งเดียวตอน mount แล้วไม่รันอีกเลย
- **"`await` ในเทมเพลตใช้ได้เลยในทุกโปรเจกต์ Svelte 5"** พิสูจน์แล้วว่าผิดด้วย compiler error จริง: ต้องเปิด `experimental.async: true` อย่างชัดเจน และยังถูกระบุว่าเป็น experimental อยู่
- **"ถ้า widget throw ได้ ครอบทั้งหน้าด้วย `<svelte:boundary>` เดียวก็พอ"** จริงในทางเทคนิค แต่หมายความว่าความล้มเหลว*ที่ไหนก็ได้*จะ unmount ทั้งหน้า วิธีแก้ในรีวิวนี้จำกัดขอบเขต boundary ไว้แค่ widget ที่พังได้จริง ๆ
- **"`$state.raw` ยัง mutate nested property ได้ แค่ข้าม deep proxy เพื่อ performance"** พิสูจน์แล้วว่าผิด: การ mutate มันไม่ใช่แค่ "optimize น้อยกว่า" แต่ระบบ reactivity เพิกเฉยต่อมันโดยสิ้นเชิง
